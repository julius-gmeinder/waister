# CLAUDE.md

## Project

**Waister** is a Manifest V3 browser extension (TypeScript, esbuild) that estimates the
**total token usage of a single prompt** in AI chat web apps: **ChatGPT** (`chatgpt.com`),
**Claude** (`claude.ai`) and **Gemini** (`gemini.google.com`). Every prompt is saved to a local
SQLite database, and the toolbar popup shows the token usage of the last 24 hours. University
project (semester 3).

## Domain

- **Prompt:** one user message plus the assistant's answer to it.
- **Visible tokens:** tokens of content that appears on the page. They are counted with a
  provider-specific tokenizer (from reconstructed markdown + whitespace runs + per-attachment
  estimates):
  - **input**: the new user message and its attachments (images, files / pasted-content cards)
  - **history**: all earlier turns (and their user attachments), which the chat app re-sends as context on every prompt
  - **output**: the visible answer plus any open Artifact / Canvas document generated by that answer
- **Hidden tokens:** tokens that never appear on the page. They are estimated:
  - **thinking**: reasoning tokens, inferred from latency, model output speed and thinking effort
  - **tools**: hidden tool-call tokens (web search result snippets, code execution inputs/outputs)
  - **overhead**: system prompt and tool definitions per model
- **totalTokens** = input + history + output + thinking + tools + overhead. This is _the_ number.
- **Provider:** `openai`, `anthropic` or `google`. **Model:** name + version + thinking effort, as
  far as the site's UI shows them.
- **latencyMs:** time from sending the prompt until the response finished streaming.
- **Prompt record:** one saved prompt = estimate + UUID + conversation URL. Metrics only, no chat
  text ([ADR 0009](docs/decisions/0009-sqlite-prompt-store.md)).

## Architecture (by layer)

```
content:     readers/  (sites/ = WHERE, strategies/ = WHEN) → ChatCaptureDto
                 │ chrome.runtime ESTIMATE_PROMPT
background:  handlers/estimation.handler (EstimationHandler)
                 ├─ services/tokenizer   (TokenizerService, one COUNTERS table)
                 ├─ services/estimation  (EstimationService + model-profiles)
                 ├─ services/conversion  (ConversionService: tokens → energy, water, CO2)
                 └─ services/prompt-store (SQLite WASM, snapshot in IndexedDB) ← PromptRecordDto
             handlers/usage.handler → services/prompt-store → UsageSummaryDto, PromptHistoryDto
popup:       ui/popup/  (React, dashboard)  ← GET_USAGE_SUMMARY (reads only the database)
                 │ tab bar → chrome.tabs.create
app page:    ui/app/    (React, full tab, hash routes: dashboard · analytics · facts · tips · history)
                 ├─ dashboard ← GET_USAGE_SUMMARY per timeframe (fetched by the App root)
                 ├─ history   ← GET_PROMPT_HISTORY pages per filter (fetched by the App root)
                 └─ analytics ← GET_PROMPT_RECORDS (all records) + CLEAR_PROMPT_RECORDS
             ui/components/ + ui/base.css + ui/app-routes.ts + ui/usage-api.ts shared by both
shared:      dto/, messages/, config/ (config.json: every tunable rate, heuristic and timing)
entries/:    one esbuild entry per context, wiring only
```

All docs live in `docs/` only. Start at `docs/README.md`. The per-module reference is
`docs/modules.md`, and decisions are in `docs/decisions/`. Don't add README files inside `src/`.

## Rules

- **Respect context boundaries.** `readers/` = content only, `handlers/` + `services/` =
  background only, `ui/` = popup + app page only. Only `dto/`, `messages/` and `config/` are
  shared. Allowed imports per layer are in `docs/architecture.md`. Never import background code
  into content/popup.
- **No magic numbers for estimation.** Rates, heuristics, effort defaults and capture timings live
  in `src/config/config.json` ([ADR 0012](docs/decisions/0012-central-config.md)), imported by
  section (`import { capture } from '…/config/config.json'`).
  Cross context only through `messages/`.
- **Plain function modules, no classes.** Handlers orchestrate, services compute, DTOs are plain
  structured-clone-safe data. React components are function components too.
- **File names:** kebab-case + role suffix (`*.entry.ts(x)`, `*.reader.ts`, `*.site.ts`,
  `*.strategy.ts`, `*.handler.ts`, `*.service.ts`, `*.tokenizer.ts`, `*.dto.ts`, `*.types.ts`,
  `*.helpers.ts` (folder-internal pure helpers), `*.app.tsx`, `*.page.tsx`, `*.component.tsx`).
  Exception, no suffix needed: folder-internal modules (`model-profiles.ts`,
  `sqlite-database.ts`) and the shared `messages/`, `config/`, `ui/app-routes.ts`,
  `ui/usage-api.ts` and `entries/css-imports.d.ts` files.
- **Comments:** every src file starts with a header comment: `/** <ModuleName>: <one line>. <optional
≤3 lines WHY>`, then `Context: content | background | popup | app page | shared` and
  `Docs: docs/modules.md#<section>` as separate lines of the same block.
  JSDoc for headers, exports and fields, `//` only for in-body WHY. Comment WHY, not WHAT. A magic
  list or selector gets a one-line reason. Don't duplicate what the docs say. Site adapters mark
  unchecked selectors with `// UNVERIFIED:` (see `site-adapter.types.ts`).
- **Lint enforces the layers:** `eslint.config.js` has `no-restricted-imports` per layer, matching
  the import table in `docs/architecture.md`.
- **UI (React):** only the `*.app.tsx` roots fetch data (through `useUsageSummary` /
  `usePromptHistory` in `ui/usage-api.ts`). Pages and `components/` only render props (and may navigate). Routes only in `ui/app-routes.ts`. Shared styles in `base.css` / `components.css`,
  surface layout in `popup.css` / `app.css`, colors only via the CSS variables
  (`docs/styling.md`).
- **Keep docs in sync:** when you add, move or change a module, update its section in
  `docs/modules.md` (and the `Docs:` anchor in the file header) and, if it affects them,
  `docs/architecture.md`, `docs/pipeline.md`, `docs/dto.md`. A structural decision gets a new
  ADR.
- Structure changes are discussed first: ask the user (questionnaire) before reorganizing.

## Status

Pipeline implemented end to end (readers → handler → tokenizer/estimation/conversion services →
SQLite prompt store). The popup (React + TSX, [ADR 0010](docs/decisions/0010-react-popup.md)) reads
the database and shows the last 24h of token usage (total, breakdown, accumulated energy, water &
CO2 tachos, prompt count). Its tab bar opens the full-page app page
([ADR 0011](docs/decisions/0011-app-page.md)). Its default page, the Dashboard
([ADR 0014](docs/decisions/0014-dashboard-page.md)), shows tokens plus the energy/water/CO2 `impact`
for a chosen timeframe in three animated cards (CSS + inline SVG), each with a fun fact drawn
fresh per visit from the Facts logic, under a token tile whose number beats and spits a coin per
beat (the token pulse, faster with more tokens per day). The History
([ADR 0015](docs/decisions/0015-history-page.md)) lists every saved prompt (timeframe, chat-app
and sort filters, day groups, "Load more" paging) with a detail modal per prompt. Facts compares
the impact with everyday benchmarks (hourly seeded pick). All pages share one look: flat tiles
modeled on the History row, shared TokenCount / ImpactBadge / Chip / ProviderIcon components, no
rules or uppercase labels ([ADR 0016](docs/decisions/0016-unified-ui-look.md),
`docs/styling.md`). Analytics breaks all saved prompts down per metric and timeframe (KPI
tiles, breakdown bar, model donut + comparison, chat memory chart, eco-insight, CSV/JSON export,
history reset) in the same look. Tips is an empty placeholder so far. `npm run check` and
`npm run build` pass.

## Commands

```sh
npm run dev        # watch build into dist/waister/ (load unpacked in the browser)
npm run dev:firefox  # same, with the Firefox manifest (also build:firefox, zip:firefox)
npm run build      # production build
npm run check      # typecheck + lint + prettier check, run before committing
npm run zip        # package for store upload
```
